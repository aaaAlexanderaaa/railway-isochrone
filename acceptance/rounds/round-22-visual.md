# round-22 视觉验收（视觉模型独立审查，2026-09-21 晚）

- 背景：用户实测后提出三点批评（①想看按小时的天气流动；②单点天气集中在右下角、UI 重复、开详情时天气不可见；③气象图只有温度，缺湿度/时间/天气类型/多模型数值），并指示"开视觉模型做独立验收：视觉模型"。
- 视觉模型 状态：网关可达但被 `service_agreement_required` 挡（需用户本人在 gateway.example.com 接受服务条款，模型侧不能代签）。本轮改用会话内视觉分析模型执行同样的独立审查循环；用户签署协议后可无缝切换 视觉模型 复验。
- 上游状态：Open-Meteo 当日免费配额（10k/日）被开发期多次全量构建耗尽，返回 "Daily API request limit exceeded. Please try again tomorrow."（北京时间明早 08:00 重置）。因此本轮视觉验证使用**合成 mock 数据**（浏览器内注入，未进入产品数据），只评估界面与信息架构。

## 针对三点批评的修复

1. **按小时的流动**：格点协议 v3——近 72 小时逐小时 + 远端 3 小时混合步长（176 步，总量与全 3h 版相当）；时间轴逐小时拖动/播放（700ms/步），今天 12:00 ↔ 明天 06:00 逐小时验证通过。
2. **UI 去重**：右下天气面板整体删除；预报模式下拉并入右上图层面板；图例+出处并入底部时间轴；**单点多模型气象图搬进站点详情页**（点开城市即可见，不再被遮挡）。配套：`body.wx-tl-on` 让详情面板/地图控件为时间轴让位。
3. **气象图要素补全**：四模型温度线、湿度绿区（右侧独立刻度 25/50/75%）、降水柱、顶部逐 3h 天气图标行、小时时刻轴、日分隔、"现在"与"到达"标记线、悬停读数（时间+天气类型+各模型温度/湿度/风速具体数值）。数据侧 point 接口增加 relative_humidity_2m / apparent_temperature。

## 遗留与风险

- **明日 08:00 前天气图层不可用**（上游日配额耗尽，无陈旧缓存可服务——落盘缓存功能是在配额耗尽后才加的）。配额重置后首个请求自动恢复并落盘；此后限流/重启期间服务陈旧缓存（含 10 分钟上游退避门）。教训：配额耗尽当天不该反复全量重建。
- 已知轻微缺陷：上游失败的在途请求会吞掉紧随其后的一次 setMode（约 60 秒窗口内再切一次即恢复）——记 backlog。
- CF 端 `functions/api/weather/*` 已同步 v3（常量与打包来自共享 core），部署后生效。
